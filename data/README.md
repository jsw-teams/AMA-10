# Training text provenance

`raw/wikipedia_train.txt` and `raw/wikipedia_validation.txt` are assembled from full plaintext extracts of English Wikipedia articles fetched through the MediaWiki API. The first six articles form training data; the last two are held out by page. `raw/wikipedia_sources.json` records the page title, page ID, exact revision ID, source URL, retrieval time, split, and CC BY-SA 4.0 license for every article. The retrieval process is reproducible with `scripts/fetch_wikipedia.ps1`.

Wikipedia text is available under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/); a copy of its legal code is in `licenses/CC-BY-SA-4.0.html`. Attribution is to the contributors listed in each source revision, linked from the URLs and revision IDs in the manifest. Any redistribution of the combined text must retain attribution and the share-alike terms.

The training file is 189,305 bytes (SHA-256 `58C7A2D0FC731A9A35FB17A759B31641068F44F3EE27CE9570615AE9764AF299`); validation is 80,852 bytes (SHA-256 `093AB2652A7065F5D34B679D3C7A167F23A121295BB0F34408C357CCF183270C`). This eight-article corpus is only a pipeline smoke corpus and is not representative of broad language ability. A separate `raw/wikipedia_cc_by_sa.txt` file is an earlier multi-page excerpt capture and is not used by the current training command.

## Synthetic tool traces

`scripts/prepare_calculator_tool_sft.ps1` creates deterministic arithmetic prompt/response examples under `processed/calculator_tool_sft/`. These are synthetic execution traces, not external text or licensed data. Each response contains the exact calculator call block, a framed untrusted result, and a final answer; `sources.json` records the seed, counts, format, and SHA-256 hashes. Keep this small capability-plumbing set separate from natural-language pretraining corpora.

The trainer fingerprints these raw files incrementally, fits BPE from a bounded training sample (8 MiB by default), and builds reusable `.ama10ds` token caches under the ignored `build/` directory. Files larger than the budget are sampled at evenly spaced byte offsets. Each cache header records the raw-file hash and tokenizer fingerprint; stale or mismatched caches are rebuilt. The current source is plain text with documents separated by blank lines; the small sample is below the default tokenizer sample budget, so the complete train split is used for BPE fitting.

## Multilingual text collection

`scripts/fetch_multilingual_wikipedia.ps1` retrieves lead introductions from separate English, Chinese, Japanese, Spanish, and French pages through each language edition's MediaWiki Action API. It requests the training and validation pages together per wiki, records page IDs, revision IDs, canonical URLs, language, retrieval time, extract scope, and CC BY-SA 4.0 license, and applies a serial delay plus `maxlag` and exponential retry backoff. Train and validation are split by page within each language. Use its outputs `raw/multilingual_train.txt`, `raw/multilingual_validation.txt`, and `raw/multilingual_sources.json` as a separate experiment; do not merge them with the original eight-page corpus without recording the combined provenance. The script follows the [MediaWiki API etiquette](https://www.mediawiki.org/wiki/API:Etiquette); rate limits apply across Wikimedia APIs, so the fetcher runs serially and backs off after failures.

For Hugging Face sources, pin an immutable repository revision, prefer documented Hub APIs and official shards over rendered-page scraping, and honor `RateLimit`/`Retry-After` headers. `scripts/fetch_hf_dataset_file.ps1` implements a deliberately slow, single-file path. `scripts/fetch_hf_librispeech_rows.ps1` uses a 30-second minimum request spacing and retry backoff for the pre-existing LibriSpeech extension. `raw/librispeech_hf_micro/` now contains 80 paired examples: 64 train and 16 validation, with no train/validation speaker overlap. `sources.json` records the pinned revision, row IDs, source splits, speaker/chapter IDs, transcripts, raw source-audio hashes, asset paths, and converted-WAV SHA-256 for every row. This remains an existing small speech experiment and does not count toward the designated FLEURS source. The canonical catalog of all 26 requested datasets is `pipeline/datasets.json`; shard and processing events are recorded in `pipeline/status.jsonl` by the C11 `ama10_pipeline_ledger` utility. These are local files: no external database service or connection string is configured. See `../docs/data_acquisition_plan.md` for lifecycle, mixture, and reporting rules.

### Polite multilingual expansion

`scripts/fetch_multilingual_expansion.ps1` writes a separate 144-page training / 36-page validation corpus (`raw/multilingual_expansion_*.txt`) across English, Spanish, French, Japanese, Chinese, German, Portuguese, Russian, and Arabic, with sixteen training leads and four held-out leads per language. It sends one grouped query per language, waits at least 30 seconds between language requests, sets `maxlag=5`, uses a descriptive User-Agent, caches each completed language batch under ignored `data/cache/`, and backs off at least 120 seconds after 429 responses while honoring `Retry-After`. Its source manifest records requested and canonical titles, page ID, revision ID, URL, retrieval time, extract scope, and CC BY-SA 4.0 license. It reuses cached titles individually when extending a language batch and rejects duplicate page IDs before writing the corpus. It does not overwrite the original five-language corpus. `scripts/split_multilingual_validation.ps1` reconstructs page-disjoint language validation files from the manifest; for multiple pages in one language it concatenates all page extracts.

The 20-language expansion is stored separately as `raw/multilingual_expansion_20lang_train.txt`, `raw/multilingual_expansion_20lang_validation.txt`, and `raw/multilingual_expansion_20lang_sources.json`. It contains 225 train and 58 validation leads; seven missing train titles are logged in `raw/multilingual_expansion_20lang_sources.missing.json`. The request interval and retry behavior are the same as above. All entries retain their page/revision attribution and CC BY-SA 4.0 license. Per-language held-out text is in `processed/multilingual_expansion_validation_20lang/`. The companion `processed/multilingual_sft_20lang/` TSVs contain 225 train and 58 validation prompt/response pairs derived from those same split pages. These small samples are for pipeline experiments, not language benchmarks.

### Rights-traceable image-caption seed

`raw/commons_captioned_seed.csv` selects three training images and one held-out image. `scripts/fetch_commons_captioned_images.ps1` makes one batched Commons metadata request with a 30-second minimum pause before follow-up requests, waits at least 30 seconds before the structured-caption request, then fetches thumbnails serially with 30-second gaps. It only accepts allowlisted free licenses, requires an English structured caption, converts thumbnails to 64x64 RGB P6 PPM with `ffmpeg`, and writes `raw/commons_captioned_seed/manifest.tsv` plus `sources.json` hashes, per-image licenses, artists, caption text, MediaInfo IDs, and source URLs. Commons file media carry individual image licenses; structured file captions are CC0. The seed's three training images are CC BY 4.0 (Alexis Lours), CC BY-SA 2.5 (Andreas Trepte), and CC BY-SA 4.0 (Tisha Mukherjee); its validation image is CC BY-SA 4.0 (Charles J. Sharp). Keep the manifest with any copy of these assets. This four-pair, single-species sample is only a multimodal pipeline experiment and is not a caption-quality benchmark.

`raw/commons_captioned_diverse.csv` adds seven separately licensed Commons images to that seed. Run `scripts/assemble_commons_captioned_diverse.ps1` to fetch those seven serially and reuse the already fetched kingfisher files without downloading them again. Then run `scripts/expand_commons_caption_languages.ps1` to fetch available English, French, Spanish, Japanese, and Chinese structured labels in one batched metadata request with a 30-second minimum pause before follow-up requests. The TSV has one row per image-caption pair and records language in column four; translated rows for an image remain in its original train or validation split. The combined manifest has 20 caption rows over 11 images: eight training and three validation images spanning birds, foxes, apples, bicycles, a mountain, and a city skyline. Its `sources.json` contains per-image SHA-256, caption language/text, attribution, MediaInfo ID, page/thumbnail URLs, and individual image license. The validation images are separate photos from training, though some subject categories overlap. This remains a tiny, mostly English caption set and is not a broad recognition benchmark.

### Language-conditioned SFT data

Run `scripts/prepare_multilingual_sft.ps1` to derive escaped prompt/response TSV from the revision-pinned Wikipedia expansion cache. It produces 144 training and 36 validation pairs, balanced across nine languages with sixteen training pages and four held-out pages per language. It preserves the article split from the source manifest, records row-level page/revision/URL/license provenance in `processed/multilingual_sft/sources.json`, and writes per-language TSVs for diagnostics. The underlying article extracts are CC BY-SA 4.0; retain their attribution and share-alike terms. This data is a tiny language-selection probe, not a benchmark of broad multilingual instruction following.

### Multilingual OASST1 conversation SFT

`scripts/prepare_oasst1_multilingual_sft.ps1` reads the local revision-pinned OASST1 export and writes balanced capped training pairs for en, es, fr, ja, zh, de, pt-BR, ru, and ar, plus per-language validation TSV/text and a message-tree provenance manifest. Train and validation are separated by whole message tree. The selected 3,670/680 pair sample has sparse Arabic (26/3) and Japanese (144/23) coverage. The Hub card declares Apache-2.0, but that declaration does not independently establish rights to each user submission; review the source and terms before redistribution.
