# AMA-10 v0: Shared Adaptive Recurrent Core

This is a falsifiable starting design, not a claim of achieved language capability. One learned recurrent cell is iterated for a bounded number of microsteps per input symbol. It has a fast state `h` and a leaky slow trace `m`; both pass across sequence positions. The shared weights across internal depth and explicit slow trace distinguish this first prototype from the reference architectures; that distinction alone does not establish an advantage.

For token embedding `x_t`, microstep `d` computes

```
u = tanh(Wx x_t + Wh h[d] + Wm m[t] + b)
g = sigmoid(Wx x_t + Wu h[d] + bg)
h[d+1] = (1-g) * h[d] + g * u
m[t+1] = rho*m[t] + (1-rho)*h[D]
z_t = W_vocab h[D]
```

The slow trace is held fixed through the token's recurrent microsteps and advances once using the final fast state. This keeps its time constant independent of recurrent depth. CPU inference caches `Wx x_t` once per token and reuses caller-owned per-state scratch vectors; it does not allocate recurrent work arrays in the token hot path. Training already caches the input projection over the sequence before recurrent-depth evaluation.

Here `g` is elementwise and `Wu` is a dense matrix. The input projection `Wx x_t` is deliberately shared by the candidate and the write gate: each token can directly affect its fast-state write, without adding a second input matrix. This weight tying is an AMA-10 design choice that needs ablation against a separate gate projection and a recurrent-only gate. The implementation uses `rho=0.995`, an experimentally unvalidated initial constant. Both inference and the adaptive trainer can stop after at least two microsteps when `c_d = 1 / (1 + mean(abs(h[d+1]-h[d])))` reaches a caller-supplied threshold, or at the maximum depth. The discrete stopping decision is treated as fixed during BPTT; gradients propagate through every executed microstep. This activity criterion is a compute heuristic, not a learned halting policy. The CLI baseline still uses fixed depth two. `evaluate <checkpoint> <tokenizer> <data> <max-depth> <threshold>` reports full-stream fixed and adaptive token NLL plus mean executed recurrent depth, allowing thresholds to be compared at matched data and model weights.

For a dense modality input `v_t` (such as image-patch or audio-frame features), a trainable frontend may map it to the shared core's input space with `x_t = tanh(A v_t + c)`. `ama10_step_features` and `ama10_train_feature_sequence` accept these core-width vectors directly; the training API returns `dL/dx_t`. `AMA10Encoder` implements the trainable dense adapter and joint frame-aligned update, using AdamW with global norm clipping. Encoder-only state can be stored in `.enc`; `ama10_multimodal_checkpoint` bundles the recurrent model, tokenizer, optimizer, recurrent state, progress, and encoder into one checksummed `.amm` file with staged writes and backup recovery. `ama10_train_multimodal_sequence` can mix feature and token inputs while masking prompt positions from loss. `ama10_train_feature_conditioned_text` conditions text on a complete feature prefix. Speech transcription training processes log-mel frames, computes CTC frame posteriors, and passes those soft targets through shared-core BPTT and the trainable audio encoder. Inference uses an 8-prefix CTC beam search with optional blank-score penalty and language-conditioned training-manifest bigram fusion. On the expanded 48/12 LibriSpeech split, held-out WER/CER remained near 1 despite lower CTC loss; these models are not usable recognizers. A separate experimental TTS trainer fits a train-only k-means codebook over pairs of 40D log-mel frames pooled to 50 frames/s, then trains the shared core autoregressively on `<lang:xx> TEXT newline NUL CODE... EOS` with causal next-token cross entropy. At generation, code IDs select codebook centroids which are converted to approximate linear magnitudes; deterministic random-phase Griffin–Lim estimates phase before overlap-add synthesis to mono PCM16 WAV. Because the current pilot does not emit EOS, inference stops at a duration estimated from training frames per transcript byte. Its validation loss is 5.735589→4.634959 after 1,101 updates, but speech intelligibility and naturalness have not been established. The image frontend decodes binary P6 PPM and patchifies RGB pixels. The audio frontend reads 16 kHz PCM16 mono/stereo RIFF WAV, averages stereo channels, computes 40 log-mel power features from a 512-point FFT of 25 ms Hamming windows at 10 ms hops, and applies a fixed per-bin scale so each frame can be computed without future utterance statistics.

For sequence-level acoustic supervision, `ama10_audio_ctc_posteriors` computes CTC forward-backward in log space from frame-major logits. It returns the transcript sequence negative log-likelihood and a normalized posterior distribution over output classes for each frame. `ama10_train_soft_multimodal_sequence` accepts these posterior targets and differentiates softmax cross-entropy through the shared recurrent core, returning gradients for dense modality inputs as usual. Finite-difference tests verify the CTC posterior is the sequence NLL gradient target. This path now drives the LibriSpeech trainer, though its small pilot still has near-total word error and poor character error.

The current experimental text-to-image path uses a train-only k-means codebook over 16×16 RGB patches and an autoregressive shared recurrent core. The `.vq` v2 sidecar records a 12×12 stride; overlapping patch reconstructions are combined by weighted averaging. The training sequence contains reserved image-code IDs, normalized 8-bin x/y coordinate markers before each code, and a distinct image EOS marker. These IDs cannot collide with the tokenizer's 256 byte fallback tokens, and ordinary text generation filters all special tokens. Grid dimensions follow the patch size and stride, so 1080×640 currently requires 4,770 codes. A two-level residual-VQ representation is implemented and tested at the codebook/reconstruction API level, but is not used by autoregressive training: its held-out fox reconstruction raised PSNR and lowered SSIM, so it has not been accepted as a quality improvement. The production trainer remains a pixel-space codebook, not a trainable convolutional encoder; it has no learned multiscale latent, cross-attention, or perceptual objective. Weighted overlap reduces seam discontinuity but does not create coherent global structure. It must not be described as a production high-resolution image model.

Training minimizes causal next-token cross entropy `L = -sum_t log softmax(z_t)[y_(t+1)] / T` over learned BPE IDs, with a 256-byte fallback vocabulary. BPE is learned from a bounded sample of the training file (8 MiB by default); large files use evenly spaced windows, and the sample budget is recorded in checkpoints. The raw files are fingerprinted in blocks, encoded once into little-endian 16-bit/32-bit token caches with raw-data and tokenizer fingerprints, then read by token cursor for updates and evaluation. This removes full-corpus byte/token arrays from the trainer after tokenizer fitting; fitting still needs memory proportional to the configured BPE sample. C code manually backpropagates through recurrent depth and sequence time. The input-conditioned gate adds `dL/dg * g*(1-g)` to the input-projection gradient as well as the candidate path; embedding gradients receive the corresponding summed input signal. In adaptive mode each token has an executed depth `D_t <= D_max`; the output is read from `h[D_t]` and BPTT unrolls exactly those transitions. State can pass between chunks, but gradients stop at chunk boundaries (TBPTT). Gradients can accumulate as token-weighted sums across multiple chunks before global norm clipping.

The Q8 inference format stores every dense matrix as signed symmetric int8 with one positive scale per output row (`s_i = max_j |W_ij| / 127`, or 1 for an all-zero row). Biases remain float32. Inference computes each row as `s_i * Σ_j q_ij x_j`; embeddings and the output head use the same row-wise rule. Fast/slow recurrent states and all activations stay float32. The checksummed `.q8` payload is independent of optimizer and training state; tokenizers are stored as a `.tok` sidecar. This reduces weight memory by roughly 4×, at the cost of small quantization error. On a width-128, vocabulary-1024 checkpoint, a recurrent-logit parity fixture measured max absolute error 0.006833 and RMS error 0.002091; the held-out English token NLL changed by 0.003429 after quantization. This is weight-only quantization, not a low-bit training path.

`ama10_kd_train` performs full-vocabulary teacher distillation in C: for each causal input token, a teacher checkpoint produces a softmax target distribution and the student minimizes soft-target cross entropy through the same recurrent BPTT path. The student reuses the teacher tokenizer but initializes a smaller recurrent model from scratch. Train and validation inputs use fingerprinted token caches; evaluation reports teacher/student KL and student gold-token NLL. The multilingual 32→16 width pilot reduced validation KL from 0.053928 to 0.024569 over 1,000 updates. This validates the pipeline and modest width reduction, but generation quality has not been established.

`ama10_lora_train` freezes a loaded base checkpoint and learns a rank-r residual on the vocabulary projection: `z = W_vocab h + s B(Ah)`, with `A ∈ R^(r×H)`, `B ∈ R^(V×r)`, and `s=r/H`. Only A and B receive Adam updates; the recurrent state and full-rank base head remain unchanged. The `.lora` file stores factors, scale, and base-checkpoint/tokenizer fingerprints, and CPU generation verifies both fingerprints before applying the residual. The implementation currently adapts only the output head and is not wired into the OpenCL decoder. On OASST1, rank 8 and 1,000 updates reduced response NLL 6.941806→6.935594, but free generation remained incoherent. This is a constrained adaptation experiment, not evidence of usable instruction following.

`ama10_supervisor` is a C checkpoint gate. It streams one validation corpus through reference and candidate checkpoints, computes next-token NLL, and produces deterministic 128-token greedy continuations while enforcing valid UTF-8. It selects the candidate only when NLL does not exceed the reference by the configured absolute tolerance, repeated 4-gram ratio rises by no more than 0.05, and candidate repeated 4-gram ratio is at most 0.75 by default (configurable); otherwise it atomically selects the reference and writes its tokenizer sidecar. When per-language validation files are supplied, it also reports the generated continuation's expected Unicode script fraction and defaults to requiring 0.50 for recognized language tags (Latin, CJK/Japanese kana, Hangul, Cyrillic, Arabic, Devanagari, and Bengali). Unknown tags keep their NLL gate and do not receive a script classification. The absolute repetition ceiling prevents an already collapsed reference from normalizing a similarly collapsed candidate. These inexpensive checks cannot judge answer correctness, grammar, or meaning, call an external teacher, launch training, or upload metrics. A width-128 OASST continuation lowered held-out response NLL 6.4018→6.1567, but both reference and candidate had a 0.992 repeated 4-gram ratio on the multilingual held-out prompt; the updated absolute gate rejected it.

Tool calls use a bounded textual envelope and a C allowlist. The dispatcher executes arithmetic locally or searches one caller-specified text file, then returns an explicitly untrusted result block for the model's next context. `ama10_tool_chat` runs generate→dispatch→append-result→generate on CPU with a fixed turn limit. This tests the integration mechanics, while a synthetic calculator-trace SFT pilot failed to elicit a call from free generation; no autonomous tool-use capability is claimed. The separate `ama10_teacher_judge` CLI uses Cloudflare Workers AI (default `@cf/openai/gpt-oss-20b`) to compare two supplied responses, validate a compact preference schema, and save a report and chosen/rejected TSV row. It reads a token from the Git-ignored root `api.key` and requires `CLOUDFLARE_ACCOUNT_ID`. The supervisor can use the same provider as an opt-in acceptance gate. SwanLab's documented REST API manages account/project resources, while experiment metric logging is provided by its SDK; AMA has no stable documented metric-ingest REST endpoint to target, so upload remains unimplemented.

`grow-vocabulary` can append BPE merges to a loaded tokenizer, preserving every old token ID and merge while adding new embedding/output rows. Existing parameters and optimizer moments are copied; new optimizer moments are zeroed, and the update count and optimizer step continue. The command requires the checkpoint's original training file so its fingerprint and merge-learning sample match. It maps the checkpoint token cursor to a raw-byte offset and then to the new token cache, and resets recurrent state because the token segmentation has changed. This is a continuation mechanism, not a controlled substitute for training a larger vocabulary from scratch.

The optimizer can use AdamW (`beta1=0.9`, `beta2=0.999`, `epsilon=1e-8`) for all parameters, or Muon for hidden matrices plus AdamW for embedding, output-head, and 1D bias parameters. Muon updates use SGD momentum 0.95 with Nesterov interpolation, five quintic Newton-Schulz iterations (`a=3.4445`, `b=-4.7750`, `c=2.0315`) on Frobenius-normalized matrix updates, and shape scaling `sqrt(max(1,rows/cols))`; decoupled weight decay is applied to both groups. Auxiliary AdamW uses 0.015 times the Muon hidden-matrix learning rate. This fixed ratio is a pilot default, not yet tuned. Optional inverse-square-root decay uses `lr(u)=lr_0/sqrt(1+lambda*(u-1))`, where `u` is the absolute optimizer update; `lambda=0` gives a constant rate. Version 6 snapshots store optimizer kind and moments alongside model weights, BPE merges, recurrent vectors and step count, global update count, token cursor, tokenizer sample size, accumulation and schedule settings, and FNV-1a fingerprints of the raw train and validation files. Version 6 changes the recurrence gate equation; earlier checkpoint versions are rejected to prevent reusing weights trained under the old dynamics. Resume requires matching data, optimizer choice, tokenizer sample size, base learning rate, decay, weight decay, sequence length, depth, accumulation setting, and target vocabulary. Snapshots are written every 100 optimizer updates and at the requested total.

With an OpenCL build, `--opencl-adamw` routes recurrent sequence forward propagation, output-head projection, sequential reverse-time BPTT, and the accumulated, globally clipped AdamW update through OpenCL. The CPU handles data loading and loss orchestration. The trajectory remains on device between forward and backward; only per-token hidden vectors return for loss calculation. Weights synchronize at sequence start and after each update; first and second moments stay on device and synchronize before checkpoint writes. Only AdamW is implemented. CPU/GPU tests compare all eight accumulated parameter-gradient groups, then compare weights and both moment arrays over consecutive updates. Current end-to-end trials at widths 64, 256, and 512 were slower than CPU, though the gap narrowed with width, so the option remains experimental.

For batch one and width `H`, input width `E`, vocabulary `V`, and fixed depth `D`, dense forward work is `O(T*(HE + D*H^2 + VH))`; adaptive depth changes the recurrent term to `sum_t D_t*H^2`, while vocabulary projection still costs `O(T*VH)`. Recurrent inference state and its reusable workspace are `O(H)` per stream, excluding model weights. This is a dense CPU baseline; measured microbenchmark results are recorded in the experiment log and should not be treated as end-to-end training throughput.

Next evidence gates: broaden finite-difference coverage; compare fixed/adaptive depth at matched compute; validate memory reset/carry and numerical stability; measure held-out text and free generation on a larger licensed corpus. Add sparse routing only after the dense gradient path passes more complete numerical checks.


A same-split codebook-capacity comparison tested 128 centers. It improved one held-out pixel score to 4.867 dB PSNR / 0.0773 SSIM, while validation code NLL increased to 5.451 and the 1080×640 image remained an unrecognizable patch mosaic. Pixel reconstruction and semantic generation are separate objectives; the present RGB patch-centroid objective does not yield a useful semantic generator.
