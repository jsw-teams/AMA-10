# Reference research log

Research date: 2026-11-17. This is an incremental survey. Entries distinguish inference/runtime implementations from systems that actually train models; repository license does not establish the license of downloaded weights or datasets.

| Project | Verified reference | Implementation lesson / caveat |
|---|---|---|
| kimi-k3-in-c | https://github.com/FareedKhan-dev/kimi-k3-in-c | Portable C99 inference, safetensors, incremental recurrent state, bounded expert cache, explicit diagnostics. Its reported 2.78T model inference is not a training result and its own docs report very low CPU token rates. |
| llm.c | https://github.com/karpathy/llm.c | MIT. Includes a roughly 1,000-line CPU fp32 C reference and C/CUDA GPT-2 training; reproducibility scripts cover larger runs. GPU path and reference checks teach optimizer/update parity. Dataset preparation and parallel PyTorch reference still use Python. The README's speed comparisons are workload- and hardware-specific. |
| llama2.c | https://github.com/karpathy/llama2.c | MIT. Its compact pure-C runtime performs Llama inference, while the training path is PyTorch (`train.py`); do not mistake this for a C trainer. TinyStories examples show the dependence of small-model results on narrow data/domain and substantial A100 compute. |
| ggml | https://github.com/ggml-org/ggml | MIT tensor/runtime foundation emphasizing low-level cross-platform operations, quantization and hardware backends; useful for AMA's later C/OpenCL kernel boundary and memory planning, not evidence of a complete pretraining pipeline. |
| llama.cpp | https://github.com/ggml-org/llama.cpp | MIT C/C++ inference runtime using ggml, with quantization and many CPU/GPU backends. It is an inference deployment reference, not a C11 from-scratch trainer; keep the language/runtime distinction explicit. |
| whisper.cpp | https://github.com/ggml-org/whisper.cpp | MIT C/C++ Whisper inference with CPU SIMD and optional accelerators/quantization. It converts and executes pretrained models; upstream weights and conversion inputs retain their own terms. Useful for streaming audio/runtime patterns, not a from-scratch C ASR training recipe. |
| CTranslate2 | https://github.com/OpenNMT/CTranslate2 | MIT C++17/Python inference engine. Converts models trained elsewhere and optimizes runtime via quantization, layer fusion and batch reordering across CPU/GPU backends. Strong deployment lessons, but its own docs explicitly require C++17 and it is not a C trainer. |
| nanoGPT | https://github.com/karpathy/nanoGPT | MIT. The current README marks the repo deprecated in favor of nanochat, but retains a readable PyTorch GPT training implementation and distributed/gradient-accumulation recipe. The GPT-2 reproduction config targets roughly 300B tokens, block length 1,024, and eight A100 GPUs for about five days; its runtime and scale are not a personal-computer baseline. |
| nanochat | https://github.com/karpathy/nanochat | MIT. Current code covers tokenizer, pretraining, SFT, RL, evaluation, and inference, with validation bits-per-byte, inference benchmarks, sampled outputs, and CORE/ChatCORE tasks. Its reported GPT-2-grade speedrun is on an eight-H100 node, so the reusable lesson is stage-specific, task-based gates and cost-aware experiment tracking, not direct C11 CPU performance transfer. |
| OLMo / OLMo-core | https://github.com/allenai/OLMo ; https://github.com/allenai/OLMo-core | The older OLMo repo says it is out of date and redirects current work to OLMo-core. OLMo-core is Apache-2.0 PyTorch training infrastructure with official `torchrun` scripts, optimizer/data/kernel modules, evaluation tooling, and staged web pretraining followed by higher-quality targeted data. It is a transparency and staged-data reference, not an all-C dependency or small-CPU recipe. Model/data licenses are separate from the code license. |
| SmolLM text training | https://github.com/huggingface/smollm/tree/main/text | Apache-2.0 repository code. The project publishes data curation, nanotron pretraining configurations, finetuning/post-training, and evaluation. The SmolLM3 report lists a 3B model trained on 11T tokens with a global batch of 2.36M, sequence length 4,096, and 384 H100 GPUs over 24 days; this makes the corpus scale and compute mismatch with AMA's 345,600-token pilot explicit. Its six-language result is not transferable without comparable data and evaluation. |
| BDH / BDH-CQ | https://github.com/pathwaycom/bdh ; https://pathway.com/introducing-bdh-cq | Investigate local neural interaction and latent iterative computation. BDH-CQ's ARC results should not be generalized to language or multimodal performance without its full protocol. |
| Mamba | https://github.com/state-spaces/mamba ; https://arxiv.org/abs/2312.00752 | Input-dependent state-space parameters enable selective retention; official implementation's optimized path is GPU-oriented, while recurrent inference can be serial. AMA has since added token-dependent gating through the shared input projection; this is a simpler gated recurrence, not Mamba's selective state-space parameterization. |
| RWKV | https://arxiv.org/abs/2305.13048 | Recurrence enables constant-size decode state and parallel scan training; distinguish paper architecture from subsequent variants. |
| xLSTM | https://arxiv.org/abs/2405.04517 | Exponential gating and scalar/matrix memory variants are useful alternatives for controlled memory updates; matrix memory increases compute/state costs. |
| Muon | https://github.com/KellerJordan/Muon | The reference explicitly assigns hidden 2D weights to momentum plus Newton-Schulz orthogonalization and embeddings, classifier/output heads, gains, and biases to AdamW. AMA implements this split in C; its small-corpus pilot is inconclusive, and the fixed auxiliary-rate ratio needs tuning. The upstream repository is MIT-licensed; see `docs/experiments.md` for the measured trial. |
| FLORES-200 | https://huggingface.co/datasets/facebook/flores | The official Hub card lists CC BY-SA 4.0 but gates access, marks the benchmark evaluation-only, prohibits model-training use, and restricts redistribution. Do not use it to train AMA or bypass the gate via a mirror. Current AMA multilingual scores use separately fetched, revision-attributed Wikipedia leads instead. |
| Wikipedia text sample | https://en.wikipedia.org/wiki/Wikipedia:Copyrights | Full extracts for six training pages and two held-out pages are captured through the MediaWiki API. Page/revision attribution and CC BY-SA 4.0 split are in `data/raw/wikipedia_sources.json`; this small sample supports only a pipeline experiment. |
| BDH-CQ | https://github.com/pathwaycom/bdh ; https://arxiv.org/abs/2608.09888 | The Pathway repository is real and public. The BDH-CQ paper describes demonstration-conditioned recurrent memory followed by latent iterative computation; its reported 29.5% ARC-AGI-1 pass@2 is specific to a 150M configuration and its evaluation protocol. The separate lucidrains repository is marked work-in-progress and is not the official implementation. The current AMA fast/slow state is not equivalent: it carries state but has no write/read separation or task-conditioned latent reasoning objective. |
| Mamba | https://github.com/state-spaces/mamba ; https://arxiv.org/abs/2312.00752 | The paper's central lesson is content-selective state updates: input-dependent state-space parameters address weak content-based reasoning in prior linear-time models. The official implementation uses PyTorch and optional CUDA extensions, so it is a mathematical/system reference, not C11 code to import. AMA's input-conditioned write gate is a simpler gated recurrence, not Mamba's selective state-space parameterization. |
| xLSTM | https://github.com/NX-AI/xlstm ; https://arxiv.org/abs/2405.04517 | The paper introduces stabilized exponential gating, scalar-memory sLSTM and matrix-memory mLSTM; the repository uses PyTorch with specialized CUDA/Triton backends. These mechanisms motivate testing explicit content-dependent retention, while matrix memory and its kernel stack are a poor fit for AMA's current small CPU budget. |
| Griffin / Hawk | https://arxiv.org/abs/2402.19427 | The paper combines gated linear recurrence (Hawk) with local attention (Griffin), arguing that a bounded local mixing path can complement constant-state recurrence. This is a useful later ablation if the current recurrent core cannot copy/retrieve nearby spans; it is not evidence that adding attention helps AMA without a matched-compute experiment. |
| Kimi K2 / K3 | https://arxiv.org/abs/2507.20534 ; https://arxiv.org/abs/2607.24653 | K2's report describes MuonClip, a large MoE pretraining run, staged agentic post-training and joint RL; K3's report describes a multimodal MoE with long-context systems work. These are frontier-scale reports, not small-CPU recipes. Their transferable lessons are to separate optimizer stability and post-training stages, instrument activated compute, and make no quality inference from sparse parameter count alone. AMA's current Muon pilot is much too small to validate MuonClip or scaling claims. |
| LibriSpeech / OpenSLR SLR12 | https://www.openslr.org/12/ ; https://github.com/danpovey/openslr/blob/master/resources/12/info.txt | OpenSLR identifies the corpus as about 1,000 hours of 16 kHz read English speech and lists CC BY 4.0. The 100-hour train-clean archive is listed at 6.3 GB; dev-clean is listed separately at about 337 MB and must remain evaluation data if used in the standard split. This is a plausible first paired ASR corpus, but its size makes a carefully selected training subset and immutable provenance necessary. Do not download the multi-gigabyte archive merely to test a decoder. |
| Hugging Face Hub dataset files | https://huggingface.co/docs/hub/main/en/datasets-audio ; https://huggingface.co/docs/hub/api | Hub datasets can store audio in several repository layouts, including large WebDataset shards. The local `fetch_hf_dataset_file.ps1` uses a descriptive User-Agent, validates machine-readable card license, resolves an immutable commit, waits between metadata and file requests, retries with Retry-After/rate-limit reset handling, and hashes the result. A repository-level license alone is not proof of underlying media rights; inspect the exact dataset card and file before training. |
| OpenAssistant OASST1 | https://huggingface.co/datasets/OpenAssistant/oasst1 ; https://arxiv.org/abs/2304.07327 | The Hub card lists Apache-2.0 and English plus 34 other languages. The ready-for-export message export contains 88,838 messages in 10,364 trees; the card says it excludes spam/deleted entries and is suitable for SFT/RM. Its flat parent/message IDs reconstruct turns, while review labels permit stricter local filtering. AMA downloads the 34.2 MB gzip export with the polite, revision-pinned fetcher, verifies its SHA-256, filters English reviewed pairs with zero spam/language-mismatch/PII/inappropriate labels, and splits by whole tree. The card license declaration is recorded; this does not constitute legal advice about upstream user submissions. |
| HuggingFaceH4 instruction-dataset | https://huggingface.co/datasets/HuggingFaceH4/instruction-dataset | The card lists Apache-2.0 and a 327-row `test` split. It was not used for training; evaluation data stays out of SFT. |
| Cloudflare Workers AI | https://developers.cloudflare.com/workers-ai/ ; https://developers.cloudflare.com/workers-ai/models/gpt-oss-20b/ | `ama10_teacher_judge` and the optional supervisor gate call the Workers AI Run API through Windows WinHTTP. The default teacher is OpenAI `@cf/openai/gpt-oss-20b`; calls are explicit and metered. Pairwise labels alone do not constitute RLAIF or safe model acceptance. |
| SwanLab | https://docs.swanlab.cn/en/api/rest/ ; https://docs.swanlab.cn/en/guide_cloud/experiment_track/log-experiment-metric.html | The public REST documentation covers platform resources but does not define stable metric-ingest endpoints. The current open-source SDK source implements project lookup/experiment creation and scalar ingestion through its own HTTP routes (`/login/api_key`, `/projects/{workspace}/{project}/series`, and `/house/metrics`). AMA-10 now has an experimental C/WinHTTP uploader matching that current SDK protocol; it is version-sensitive and is not represented as a public API. No live upload has been verified. |

These references were checked against their project READMEs and license pages on the survey date. The remaining bibliography is still open work: inspect each repository/paper's actual training path, evaluation protocol, performance context, and license before borrowing design ideas. No reference code has been copied into AMA-10.

## Design implications for AMA-10

- Keep training evidence separate from inference engineering. `llm.c` offers a C training/update reference; `llama2.c`, `llama.cpp`, `whisper.cpp`, and CTranslate2 primarily inform deployment and do not satisfy the all-C training requirement.
- Treat model weights, corpus, tokenizer, and runtime source as separate license/provenance objects. An MIT runtime does not make a converted third-party checkpoint MIT.
- Establish numerical parity and held-out evaluation before optimizing CPU kernels. Hardware speedups from CUDA, SIMD, or quantization are not architecture-quality evidence.
- Treat training scale and evaluation as part of any capability claim: current 7,200-update AMA width-32/128 runs expose only 345,600 training targets, while public nanoGPT and SmolLM recipes operate at hundreds of billions or trillions of tokens and use standard task evaluations. This scale gap explains neither every failure nor an excuse to claim success; it identifies data volume, curriculum, and task evaluation as major experimental variables that remain uncontrolled.
- AMA has added input-conditioned state writing using the shared `Wx x_t` projection. The matched-seed pilot in `docs/experiments.md` modestly improved held-out bits/byte on its small corpus, but does not isolate broader language capability. Next compare the tied projection against a separate gate projection and recurrent-only gate with multiple seeds, full held-out streams, and equal update/compute budgets. The input-conditioned recurrence is recorded in checkpoint v6; any further equation change must start from random weights rather than resume an incompatible checkpoint.
- Treat learned stopping and latent reasoning as separate mechanisms. The current activity threshold stops computation based on change magnitude; BDH-CQ instead trains recurrent latent computation around a task protocol. Do not describe the former as learned reasoning or ACT until a trained halting objective and task evaluation exist.
